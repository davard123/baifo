# 忌日 / 清明 年度提醒 —— 启用步骤

代码已经写好并通过类型检查，但**默认是关的**，线上目前没有任何行为变化。

关着的原因不是没写完，是这件事牵涉两个只有你能拍板的决定：

1. **隐私姿态会变。** 站内现在对用户承诺「照片和姓名只保存在本地设备，不会上传服务器」。
   要发年度提醒，就必须把邮箱和先人忌日存到数据库。这跟现有承诺不冲突（照片姓名仍在本地），
   但隐私说明需要补一句，说明邮箱会被保存、用途是什么、怎么退订。
2. **这是主动发信。** 站内现有的邮件都是用户点了提交之后的即时回执；提醒是一年后自己发出去的。
   退订、防重发、发信频率这些我都做了，但「要不要开始给用户发信」应该你来决定。

---

## 三步启用

### 1. 建表

Supabase SQL Editor 里执行：

```bash
worker/migrations/001_reminders.sql
```

单独一张 `reminder_subscriptions` 表，没有动 `ancestor_wishes`。已开 RLS，只有 worker 的
service_role 能访问。

### 2. 打开定时任务

`worker/wrangler.toml` 追加：

```toml
[triggers]
crons = ["0 1 * * *"]
```

UTC 01:00 = 北京时间 09:00，提醒当天早上到。然后部署 worker：

```bash
cd worker && npx wrangler deploy
```

### 3. 打开前端入口

祭祖表单里的「每年忌日与清明提醒我回来祭拜」勾选框由构建变量控制，默认不渲染：

```bash
cd frontend && VITE_REMINDERS=on npm run build
```

同时记得在隐私说明里补上邮箱用途那句话。

## 实现要点

| 关注点 | 做法 |
|---|---|
| 默认关 | 没勾选就绝不把邮箱写进订阅表 |
| 防重发 | `last_sent_on` 等于今天就跳过，定时任务重复触发不会重复发信 |
| 退订 | 每条订阅一个不可猜测的 `unsub_token`，邮件底部链接直达，无需登录 |
| 频率 | 每人每位先人每年最多两封（忌日 + 清明） |
| 单封失败 | 不中断整批，计入 `failed` 返回 |
| 时区 | 按北京时间判断「今天」，符合国内过节的日期认知 |
| 清明 | 固定按 4 月 4 日。真实清明在 4/4–4/6 浮动，提前或当天到都合适，不值得引天文历算依赖 |
