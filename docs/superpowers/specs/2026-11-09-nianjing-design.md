# 念经板块（自己看拼音念经，页面听声音往前走）设计

2026-11-09，和 David 讨论后定稿。标「我的判断」的是 Claude 做的决定，David 没有明确说过，他看的时候可以推翻。

## 为什么做

fopusha.com 上已经有诵经板块 /jing/：放录好的诵读或唱诵音频，经文跟着音频亮起来。**这次要做的不是这个。**这次是让用户**自己出声念**，经文每个字上面标拼音，页面听用户念到哪里，就走到哪里。两者没有关系，不要把新功能做成 /jing/ 的一个模式，也不要套它的音频跟读逻辑。

用户主要用手机和 iPad，很少用电脑。**国内也必须能用**（包括在微信里打开）。

## 要做到的

1. 经文：先用现有的 12 部，以后再加。
   - /jing/ 已经有的 7 部（心经、大悲咒、普贤行愿品偈颂、金刚经、普门品、阿弥陀经、地藏经），直接用 `frontend/src/data/sutras/*.js` 里的经文和拼音。
   - 另外 5 部（往生咒、六字大明咒、十小咒、药师灌顶真言、药师经），从 `D:\document\念佛板块\text\*.json` 导入。每部都有 `lines[]`，每行有 `text` 和 `pinyin`，都已经两源对照校对过。
   - 拼音以文件里的为准，比如「般若」读 bō rě、「南无」读 nā mó，不要用拼音库重新生成。
2. 每个汉字上方标拼音（ruby），标点不标。
3. 画面布局：
   - **手机竖屏**：一屏只显示一种模式，可以在两种模式间切换。
     - **卡拉OK**：上半部分是对应的佛菩萨像，慢慢推近、平移；下半部分居中放大当前这一句，念过的字变金色，正在念的字用另一种强调色；上一句淡淡显示，下一句小字预告。
     - **提词器**：整篇经文竖着排，当前这一句有底色，固定在屏幕上方大约三分之一处，随着念往上滚；用户可以用手指上下拖，拖完从拖到的地方接着走。
   - **横屏（平板或横过来的手机）**：分左右两栏，同时显示。
     - 左栏：佛像加一句一句走，就是卡拉OK的样子。
     - 右栏：像一本书，一页一页显示。念到这一页最后一句就自动翻页；也可以手动翻（左右滑动或点按钮）；也可以跟着声音走。
   - 样子参考对话里给 David 看过的示意图：暖色纸面、深棕色字、金色表示念过的字。
4. 往下走的三种方式，用户自己选：
   - **听我念**（默认）：听用户的声音，判断念到哪里。
   - **自动**：按固定速度往下走，速度可以调。
   - **手动**：点「下一句」按钮，或者在屏幕上滑。
   - 不管哪种方式，用户随时点任意一句，都从那一句接着走。
5. 背景声，用户自己选：
   - **木鱼**：按固定节拍敲，节拍快慢可以调。这是 David 定的：固定节拍，不是念一个字敲一下。
   - **佛乐**：低音量循环。
   - **静音**。
6. 卡拉OK模式和横屏左栏用的佛菩萨像，按经文对应（这是 David 定的）：
   - 心经、普门品、大悲咒、六字大明咒 → 观音
   - 阿弥陀经、往生咒 → 阿弥陀佛
   - 药师经、药师灌顶真言 → 药师佛
   - 地藏经 → 地藏
   - 金刚经、十小咒 → 释迦牟尼佛
   - 普贤行愿品 → 普贤

   一尊像有几种造型的（见 `src/data/buddhas.js`、`/buddha-variants/`），随机选一种。

## 不做的

- 不录用户的声音，不上传任何音频或识别出的文字。识别全部在本机完成。
- 不打分，不判断念得对不对，只负责跟上位置。
- 不放录好的诵读或唱诵（那是 /jing/ 的事）。

## 做砸了的标准

- 国内手机或微信里点「听我念」完全不动。
- 位置乱跳：识别对不上时宁可不动，也不能往前跳一大截。
- 经文或拼音出错。经文一个字都不能错，只能从上面列的已校对来源取。

## 语音识别（关键部分）

照搬 David 自己的提词器项目，那边已经在用：

- 安卓悬浮提词器 `D:\document\teleprompter-app`：
  - `VoiceEngine.java`：Vosk 离线中文识别。
  - `ScriptAligner.java`：把识别结果转成模糊拼音（平翘舌、前后鼻音、n 和 l 都不分），只拿最后 10 个字，在「当前位置往回 12 个字、往前 60 个字」的范围里用动态规划找最佳匹配。分数不够就返回 -1，位置不动。
- 电脑提词器 `D:\document\pc-teleprompter`（`voice.py`、`aligner.py`）：同样的做法，模型在 `model-cn`（Vosk 中文小模型，解压后 66MB）。
- iPhone 提词相机 `D:\document\teleprompter-ios`：用苹果系统自带的识别（expo-speech-recognition）。

网页版的做法：

- **识别引擎**：用 vosk-browser（WASM，在 Web Worker 里跑）加载同一个中文小模型。iOS Safari 如果有 `webkitSpeechRecognition`，可以优先用系统自带的（我的判断）；其他浏览器和微信里一律用 Vosk。
- **找位置**：把 ScriptAligner 改写成 JS，算法和参数照原样。
  - 经文这边：每个字的拼音用经文文件里校对过的，再做同样的模糊处理。
  - 识别结果这边：没有人工拼音，要用拼音库（例如 pinyin-pro）转。所以对多音字要宽松一点：经文里一个字，校对拼音和它的常见读音都算对上（我的判断）。
- **模型托管**：模型压缩后大约 40MB，超过 Cloudflare Pages 单个文件 25MB 的上限，不能放在 `public/` 里。可以放 R2 并配跨域访问，或者拆成几块、在浏览器里拼起来，由实现的人选（我的判断）。第一次点「听我念」时才下载，下载时显示进度，存进 Cache Storage，以后不用再下。
- **兜底**：模型下载失败、手机不支持 WASM、或者没给麦克风权限时，提示一句原因，然后自动切到「自动」模式。
- **识别范围**（可选）：Vosk 小模型支持把识别范围限定在一组词里。如果实测限定成本部经的字能明显变准，就加上。

## 页面与入口（我的判断）

- 路由：`/nianjing/` 是经目列表，`/nianjing/:slug` 是念经页。繁体版跟着现有 `/zh-hant/` 机制走。
- 首页顶部导航（Home.vue 的 `homeNav`）在「诵经」后面加「念经」，指向 `/nianjing`。
- 每部经记住上次念到哪一句（localStorage），下次打开问一句：「从上次的地方接着念吗？」
- 字号可以调，分大、中、特大三档，照顾老人。
- 屏幕常亮：用 Wake Lock API，不支持就算了。
- SEO：列表页正常收录；单部经页面如果 /jing/ 已经有同一部经，canonical 指向 /jing/ 那一页，避免重复内容。
